# 模块边界

## 1. 原则

1. **目录即模块**：一目录一职责，禁止跨层乱引用实现细节。  
2. **边端插件化**：主机只依赖 `CameraPluginAbi`；实现放在 `edge_agent/plugins/`。  
3. **控制面微服务**：服务间不 import 对方包，只走 **HTTP / MQ**。  
4. **公共库单向依赖**：`emp_common` / `emp_py` ← 服务；服务 ↛ 反向污染公共库业务。  
5. **协议与配置外置**：迁移 SQL、Compose、环境变量是契约的一部分。  

## 2. 模块一览

```text
platform/
  libs/emp_common     # C++ 公共（日志/插件/JPEG/环缓）
  libs/emp_py         # Python 公共（鉴权/DB/MQ/追踪）
  services/
    device_service    # 设备域
    session_service   # 会话域
    media_indexer     # 资产索引域
    alarm_service     # 告警域
    control_bff       # 聚合与登录
    edge_agent        # 边端主机 + plugins/
    media_gateway     # 预览/VOD 网关
    media_worker      # MQ 消费
  clients/control_client  # Qt 控制端（可选）
  infra/              # compose、迁移、prometheus、traefik
```

## 3. 允许的依赖方向

```text
plugins.so ──ABI──► edge_agent ──HTTP──► device/session/indexer
control_client ──HTTP──► control_bff ──HTTP──► device/session/alarm
device ──Redis/MQ──►（缓存/事件）──► media_worker
全体 Python 服务 ──► emp_py ──► PG/Redis/RabbitMQ
edge_agent / gateway ──► emp_common
```

禁止：`device_service` import `alarm_service` 内部函数；禁止插件依赖 `edge_agent` 内部类。

## 5. 变更时怎么拆 PR（建议）

- 只改公共库 + labs  
- 只改单一微服务 + 对应 Sxx 文档  
- 边端/网关 C++ 与 Python 控制面尽量分开提交
