# 企业级成熟度评估（诚实版）

> 更新日期：随仓库演进更新。目标：可上线园区/工业边缘视频平台水平。

## 总评

| 维度 | 现状 | 目标 |
|------|------|------|
| 架构拆分 | 微服务化（设备/会话/索引/告警/BFF/边端/网关/worker） | 保持 |
| 数据层 | micromamba PG + **Compose `emp_postgres` 已验证** | 多环境配置统一 |
| 中间件 | Redis/MQ + DLQ + **幂等消费** | 可配置重试/延迟队列 |
| 安全 | **写接口 JWT/API Key 双模**；心跳仍开放 | RBAC 细粒度 + 审计强制 |
| 可观测 | 日志 + metrics + **X-Trace-Id 传播** | OpenTelemetry 全链路 |
| 媒体能力 | JPEG 预览 + **回放索引 API** + ffmpeg H.264 脚本 | 真流媒体/MPP |
| 工程化 | e2e（双模鉴权/trace/preview/JWT）+ CI | 灰度与配置中心 |
| 文档 | S00–S17；S18 文档中；S03 Compose PG 勾选 | 板端实机 |

**一句话**：联调企业骨架增强（双模鉴权、追踪头、幂等、Compose PG）；上生产前还需 RBAC/审计、OTEL、真编码流。

## 本轮已落地

1. `require_auth`：X-API-Key 或 Bearer JWT  
2. 会话/资产/告警/设备写接口统一双模；边端 curl 带 API Key  
3. `X-Trace-Id` / `traceparent` 中间件  
4. MQ `event_id` + worker 幂等闸门  
5. `/api/playback/{session}` 回放索引；`encode_session_h264.sh`  
6. Compose PostgreSQL 实跑 healthy  

## 下一轮补齐重点

1. 角色 RBAC（admin/operator/device）与审计表强制写入  
2. OpenTelemetry SDK 替换轻量 tracing  
3. 边端设备凭证（非共享 API Key）  
4. RK3588 实机 + MPP 硬编
