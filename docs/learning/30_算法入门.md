- 把「有界延迟 / 背压 / 丢帧」当成媒体侧算法策略

## 2. 概念详解

### 2.1 复杂度 O 记号（够用版）

| 记号 | 含义 | 例子 |
|------|------|------|
| O(1) | 与规模无关 | 哈希均摊、环缓 push |
| O(log n) | 每次折半 | 二分查找 |
| O(n) | 扫一遍 | 找最大帧号 |
| O(n log n) | 高效排序 | 快排/归并均摊 |
| O(n²) | 双层循环 | 简单选择排序 |

边端热路径（每帧）必须接近 **O(1)**，重活丢给异步 worker。

### 2.2 排序

- 用途：按时间戳整理索引行、按严重级别排告警。  
- 本仓 `frames.index` 已是采帧顺序写入，通常无需再排；回放乱序时再排。

### 2.3 二分查找

有序数组上找边界：例如「找第一个 ts >= T 的帧」。  
伪代码：lo/hi 收窄，直到锁定下标。

### 2.4 滑动窗口

固定或可变窗口在序列上滑动：统计窗口内字节数、丢帧率。  
媒体码率控制常隐含窗口思想。

### 2.5 背压与丢弃策略（本仓算法）

```text
生产者快、消费者慢
  → 有界环缓满
  → push_overwrite：丢掉最旧，保留最新（监控预览友好）
```

这是 **策略算法**，不是教科书排序题，但企业音视频天天用。

## 6. 自测题

1. 为什么热路径避免 O(n²)？  
2. 监控预览为何偏好丢旧而不是阻塞？  
3. 幂等键用哈希 event_id，最坏碰撞怎么缓解？  

答案：1）帧间隔毫秒级；2）保证低延迟；3）用加密哈希/足够长 id，冲突极低。
