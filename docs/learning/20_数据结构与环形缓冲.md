## 2. 概念详解

### 2.1 常见结构速览

| 结构 | 典型操作 | 复杂度直觉 | 媒体场景 |
|------|----------|------------|----------|
| 动态数组 `vector` | 尾部增删 | 均摊 O(1) | 帧列表、配置 |
| 栈 | 后进先出 | O(1) | 解析、回退 |
| 队列 | 先进先出 | O(1) | 任务排队 |
| 哈希表 `unordered_map`/`dict` | 键查找 | 均摊 O(1) | 会话登记、设备索引 |
| **环形缓冲** | 定长覆写 | O(1) | 采集↔消费速度不匹配 |

### 2.2 为什么要有界

采集 30fps、编码/落盘偶发卡顿时，若无限堆积：

- 内存涨到 OOM  
- 延迟越来越大（看的是「很久以前」的帧）  

企业视频常见策略：**丢旧保新**（最新画面优先）或 **丢新**（保证完整序列，少用）。

### 2.3 环形缓冲原理

固定 `capacity` 的数组，两个下标：

- `head`：下次写入位置  
- `tail`：下次读取位置  
- `size`：当前元素个数  

写入时 `head = (head+1) % capacity`。满了再写：覆盖最旧，并 `tail` 前移。

### 2.4 本仓实现要点

```cpp
void push_overwrite(const T& item);  // 满则丢旧
std::optional<T> pop();              // 空则 nullopt
```

- 模板：同一套代码缓冲 `EmpFrameMeta`。  
- `mutex`：教学级线程安全；高性能会用无锁环缓。  
- `edge_agent`：`ring.push_overwrite(meta)` 即使后面没全部 `pop`，也演示策略。

### 2.5 与 Redis List / MQ 队列对比

| | 进程内 RingBuffer | Redis List | RabbitMQ |
|--|-------------------|------------|----------|
| 位置 | 边端内存 | 中间件 | 中间件 |
| 持久 | 否 | 可选 | 可持久 |
| 用途 | 微秒级帧缓冲 | 跨进程缓存/队列 | 领域事件 |

## 6. 自测题

1. 有界缓冲「丢旧保新」对监控预览的意义？  
2. `optional` 空与抛异常，哪种更适合高频采帧路径？  
3. 环缓满时若改成阻塞等待消费者，优缺点？  

答案要点：1）延迟可控、画面新；2）optional/错误码更轻；3）不丢帧但可能堵采集。
