## 2. 概念详解

### 2.1 编译与链接（先建立心智模型）

```text
.cpp 源码 ──编译──► .o 目标文件 ──链接──► 可执行文件或 .so
头文件 .h/.hpp 只声明；实现可在 .cpp 或头文件模板里
```

本仓用 **CMake** 描述：静态库 `emp_common` + 可执行文件 + 插件共享库。

### 2.2 类型、引用、`const`

```cpp
int w = 320;           // 值
int& rw = w;           // 引用：另一名字，不拷贝
const int& cr = w;     // 只读引用，避免误改
std::string s = "a";   // 动态字符串（堆上管理）
```

本仓：`emp::DeviceCode` 实际是字符串别名（见 `Types.h`），日志里拼 `std::string`。

### 2.3 命名空间

```cpp
namespace emp {
  class Logger { /* ... */ };
}
emp::Logger log("edge_agent");
```

避免与全局符号冲突；插件导出用 C 链接则不进 C++ 名字修饰。

### 2.4 类、构造、RAII

**RAII**：资源获取即初始化——构造拿锁/开文件，析构自动释放。

```cpp
{
  std::lock_guard<std::mutex> lock(mu_);  // 构造加锁
}  // 离开作用域析构解锁
```

`RingBuffer` 的 `push_overwrite` / `pop` 都用 `lock_guard`，防止多线程数据竞争（教学级，非无锁）。

### 2.5 模板

```cpp
template <typename T>
class RingBuffer { /* 同一套逻辑服务 EmpFrameMeta 等类型 */ };
```

编译期生成具体类型代码；头文件实现常见于模板。

### 2.6 智能指针与裸指针（本仓现状）

插件相机目前是 **C ABI 裸指针**（`EmpCamera*`），由 `create`/`destroy` 配对。  
学习时记住：企业 C++ 更倾向 `unique_ptr`；跨 `.so` 边界常退回 C ABI。

### 2.7 `extern "C"` 与插件 ABI

C++ 会名字修饰（mangling）；动态加载需要稳定符号名：

```cpp
extern "C" EmpCamera* emp_cam_create(void);
```

主机 `dlsym` 按字符串找符号。详见 `PluginLoader`。

### 2.8 头文件包含

```cpp
#include <string>           // 标准库用 <>
#include "emp/Logger.h"     // 本仓头用 ""
```

`#pragma once`：同一编译单元只包含一次。

### 2.9 边端里的 `system`/`curl`

`edge_agent` 用 `std::system("curl ...")` 调 HTTP——**教学简化**；生产应 libcurl 或自建 HTTP 客户端并处理返回码。注意命令注入：JSON 里勿拼未转义用户输入。

## 6. 自测题

1. `lock_guard` 离开作用域会发生什么？若中途 `return` 呢？  
2. 为什么插件入口要 `extern "C"`？  
3. `push_overwrite` 在满环时丢的是新帧还是旧帧？  

答案：1）自动解锁，return 也会析构；2）稳定符号供 dlsym；3）丢旧保新。
