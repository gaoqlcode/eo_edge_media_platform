# 70 · 音视频与 RK3588（加厚）

## 1. 学习目标

- 画清本仓从采帧到预览/成片的完整数据路径  
- 分清 JPEG 预览、H.264 成片、playback 元数据三者职责  
- 能按 [S18](../rebuild/S18_RK3588移植.md) 在无板时做检查单精读  

## 2. 概念详解

### 2.1 三条媒体路径

```text
① 预览热路径（低延迟）
   grab 元数据 → 测试 RGB → JpegWriter
   → data/preview/<device>/latest.jpg
   → GET :9101/preview?device=

② 会话落盘（可回看帧）
   → data/sessions/<sess>/cam0/N.jpg + frames.index

③ 成片（可下载）
   → encode_session_h264.sh → cam0/preview.mp4
   → 登记 asset_type=h264_mp4
   → GET :9101/vod?session=
```

indexer 的 `/api/playback/{session}` **只返回索引**，不传视频字节。

### 2.2 为何预览用 JPEG

- 实现简单、跨语言易显示  
- 分辨率可单独降（本仓 320×180）控制带宽  
- 企业也可改成 MJPEG over HTTP；本仓教学用「文件 + 网关读盘」

### 2.3 插件与像素

当前 Virtual/Stub **只产出元数据**；RGB 由主机 `make_test_pattern_rgb` 生成。  
真相机插件应逐步改为：DQBUF 得到真实像素 → 再 JPEG/硬编。ABI 先稳定。

### 2.4 帧索引 `frames.index`

每行示例：`frame_id,ts_ns,width,height,path`  
用途：回放定位、对时、抽帧；算法章「二分找时间戳」的数据源。

### 2.5 RK3588 与 WSL 差异

| | WSL | RK3588 |
|--|-----|--------|
| 架构 | x86_64 | aarch64 |
| 相机 | 常无，用 Virtual | `/dev/videoX` |
| 编码 | ffmpeg libx264 | 宜 MPP 硬编 |
| 部署 | 前台跑 | systemd |

详细步骤、systemd 示例、MPP 路线：见 **S18**（已加厚）。

## 5. 动手实验

```bash
cd /home/gaoql/eo_edge_media_platform
cmake --build build -j$(nproc)
EMP_ROOT=$PWD EMP_ENCODE_H264=1 EMP_FRAMES=5 EMP_DEVICE_CODE=edge-demo \
  EMP_DATA_ROOT=$PWD/data/sessions EMP_PREVIEW_ROOT=$PWD/data/preview \
  ./build/bin/edge_agent ./build/lib/libemp_cam_Virtual.so

SESS=$(ls -dt data/sessions/sess-edge-* | head -1 | xargs basename)
EMP_PREVIEW_ROOT=$PWD/data/preview EMP_SESSION_ROOT=$PWD/data/sessions \
  ./build/bin/media_gateway &
curl -o /tmp/p.jpg "http://127.0.0.1:9101/preview?device=edge-demo"
curl -o /tmp/v.mp4 "http://127.0.0.1:9101/vod?session=$SESS"
file /tmp/p.jpg /tmp/v.mp4
```

## 6. 自测题

1. 只有 preview 没有 vod，可能缺哪几步？  
2. 为何 `/vod` 要禁止 `session` 含 `..`？  
3. 板端硬编替换时，哪些模块可以不动？  

答案：1）ffmpeg/编码失败或 EMP_ENCODE_H264=0、gateway SESSION_ROOT 不对；2）路径穿越读盘；3）ABI/网关/indexer 契约可保持，换 Writer/插件实现。
