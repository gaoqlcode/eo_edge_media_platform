# 05 · 环境软件下载与工具链

## 1. 学习目标

- 能在 WSL/Ubuntu 上用 **apt / micromamba / pip / docker / cmake** 装齐本项目依赖  
- 能区分「系统工具」「Python 包」「容器镜像」「本仓源码编译」四类下载  
- 能把 Local 中间件与 Compose 中间件端口对上号并验收  

对应复刻：[S00_环境与SSH](../rebuild/S00_环境与SSH.md)、[S03_基础设施Compose](../rebuild/S03_基础设施Compose.md)

## 2. 概念：软件从哪来

| 类型 | 典型命令 | 装到哪里 | 本项目例子 |
|------|----------|----------|------------|
| 系统包 | `sudo apt install` | `/usr` | git、g++、cmake、libjpeg-dev、ffmpeg、docker |
| 独立环境 | micromamba / conda | 仓库 `.tools/mamba_root` | emp 环境里的 python、postgresql |
| Python 包 | `pip install` | 当前环境 site-packages | FastAPI、PyJWT… |
| 容器镜像 | `docker pull` | Docker 本地镜像库 | postgres:16、redis:7 |
| 本仓二进制 | `cmake --build` | `build/bin`、`build/lib` | edge_agent、*.so |

**原则**：系统级工具用 apt；可复现的 Python/PG 优先 micromamba 或 Compose；业务代码用 CMake/pip。

## 3. apt：系统工具链

### 为什么需要

没有 `g++`/`cmake` 编不出 C++；没有 `libjpeg-dev` 链不上 JPEG；没有 `git` 无法版本管理。

### 推荐命令

```bash
sudo apt update
sudo apt install -y \
  git build-essential cmake pkg-config \
  libjpeg-dev \
  python3 python3-pip python3-venv \
  curl ca-certificates \
  ffmpeg \
  docker.io docker-compose
```

可选（调试网络）：`netcat-openbsd`、`postgresql-client`（若用系统 psql）。

### 验收

```bash
git --version
cmake --version
g++ --version
pkg-config --exists libjpeg && echo jpeg_ok
ffmpeg -version | head -1
```

### 常见失败

| 现象 | 处理 |
|------|------|
| `apt` 403 / 超时 | 换官方 `archive.ubuntu.com` 或可用镜像源；`sudo apt update` 再装 |
| 无 sudo | 用已有 micromamba 路径；系统包请管理员装，或文档记录缺口 |
| `libjpeg` 链接失败 | 确认装的是 `libjpeg-dev`（含头文件），不是只有 runtime |

## 4. micromamba：本机 emp 环境 + PostgreSQL

### 为什么需要

Docker 拉镜像慢或不可用时，用 micromamba 在仓库内起 **PostgreSQL + Python**，与系统隔离。

### 本仓约定路径

```text
.tools/bin/micromamba
.tools/mamba_root/envs/emp/   ← emp 环境
.run/pgdata/                  ← PG 数据目录
```

### 推荐用法

```bash
cd /home/gaoql/eo_edge_media_platform
export MAMBA_ROOT_PREFIX="$PWD/.tools/mamba_root"
# 若已有 emp 环境：
export PATH="$PWD/.tools/mamba_root/envs/emp/bin:$PATH"
which python
python -c "import sys; print(sys.executable)"
```

一键起本机中间件：

```bash
bash scripts/start_infra_local.sh
# 期望：PG 127.0.0.1:55432 用户 emp；Redis 127.0.0.1:56379
```

### 验收

```bash
pg_isready -h 127.0.0.1 -p 55432 -U emp
redis-cli -p 56379 ping   # 应返回 PONG
```

### 常见失败

| 现象 | 处理 |
|------|------|
| `pg_ctl: cannot be run as root` | 用普通用户 `gaoql` 跑脚本，不要用 root |
| 端口占用 | 改 `EMP_PGPORT` / `EMP_REDIS_PORT`，并同步改 `DATABASE_URL`/`REDIS_URL` |

## 5. pip：Python 业务依赖

### 为什么需要

控制面微服务依赖 FastAPI 等，见仓库根目录 `requirements.txt`。

### 推荐命令（在 emp 环境内）

```bash
cd /home/gaoql/eo_edge_media_platform
EMP_PY=".tools/mamba_root/envs/emp/bin/python"
"$EMP_PY" -m pip install -U pip
"$EMP_PY" -m pip install -r requirements.txt
```

国内镜像示例（可选）：

```bash
"$EMP_PY" -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 验收

```bash
"$EMP_PY" -c "import fastapi,sqlalchemy,jwt,redis,pika; print('py deps ok')"
```

### 常见失败

| 现象 | 处理 |
|------|------|
| 装到系统 Python | 确认 `which python` 指向 `.tools/.../emp/bin/python` |
| pydantic 大版本冲突 | 本仓锁定 `pydantic>=1.10,<2`，勿强升 v2 |

## 6. Docker / Compose：企业中间件镜像

### 为什么需要

生产/联调常用容器：PostgreSQL、Redis、RabbitMQ、Traefik、Prometheus。

### 下载镜像

```bash
# 直连 Docker Hub（可能超时）
sudo docker pull postgres:16
sudo docker pull redis:7

# Hub 超时：DaoCloud 镜像站再 tag 成本地名
sudo docker pull docker.m.daocloud.io/library/postgres:16
sudo docker tag docker.m.daocloud.io/library/postgres:16 postgres:16
sudo docker pull docker.m.daocloud.io/library/redis:7
sudo docker tag docker.m.daocloud.io/library/redis:7 redis:7
```

### 启动

```bash
sudo docker-compose -f platform/infra/docker-compose.yml up -d
# 或只起 PG：
sudo docker-compose -f platform/infra/docker-compose.yml up -d postgres
```

### 验收

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
sudo docker exec emp_postgres pg_isready -U emp -d emp_platform
```

### 端口对照（勿混用 URL）

| 服务 | Local | Compose |
|------|-------|---------|
| PostgreSQL | 55432 | 5432 |
| Redis | 56379 | 6379 |
| RabbitMQ AMQP | 5672（常与 Compose 共用已有容器） | 5672 |
| RabbitMQ 管理台 | — | 15672 |

Compose PG 时：

```bash
export DATABASE_URL="postgresql+psycopg2://emp:emp_dev_pass@127.0.0.1:5432/emp_platform"
export REDIS_URL="redis://127.0.0.1:6379/0"
```

## 7. CMake：编译本仓 C++

### 为什么需要

`edge_agent`、`media_gateway`、相机插件 `.so`、labs 都靠 CMake。

### 推荐命令

```bash
cd /home/gaoql/eo_edge_media_platform
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

### 产物

```text
build/bin/edge_agent
build/bin/media_gateway
build/bin/lab_ringbuffer
build/lib/libemp_cam_Virtual.so
build/lib/libemp_cam_V4L2_Stub.so
```

### 验收

```bash
./build/bin/lab_syntax
EMP_FRAMES=2 ./build/bin/edge_agent ./build/lib/libemp_cam_Virtual.so
```

### 常见失败

| 现象 | 处理 |
|------|------|
| `undefined reference to pthread_create` | CMake 已链 `Threads::Threads`；重新 configure |
| 找不到 `jpeglib.h` | 安装 `libjpeg-dev` 后清 build 再 cmake |

## 8. SSH：访问 GitHub

### 为什么需要

本仓远端是 SSH：`git@github.com:gaoqlcode/eo_edge_media_platform.git`。

### 推荐命令

```bash
ssh-keygen -t ed25519 -C "your@email" -f ~/.ssh/id_ed25519 -N ""
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
# 粘贴到 GitHub → Settings → SSH and GPG keys
ssh -T git@github.com
```

期望：`Hi gaoqlcode! You've successfully authenticated...`

详解工作流见 [Git 工作流](../ops/git_workflow.md)。

## 10. 自测题

1. 说明 apt 与 pip 分别解决什么问题，能否互相替代？  
2. Local PG 与 Compose PG 端口各是多少？混用 `DATABASE_URL` 会怎样？  
3. Hub 超时如何用 DaoCloud 得到本地名为 `postgres:16` 的镜像？  

答案要点：1）系统/解释器包 vs 语言库；2）55432 vs 5432，连错库或连不上；3）pull 镜像名再 `docker tag`。
